## Objectif du guide

Ce guide aide a utiliser l'intelligence artificielle comme assistant de production sans abandonner la responsabilite humaine.

A la fin du guide, le lecteur doit pouvoir appliquer cinq responsabilites :

1. piloter la demande ;
2. controler le contenu ;
3. corriger les erreurs ;
4. valider la version utile ;
5. assumer le livrable produit.

## Pour qui ?

Ce guide s'adresse :

- aux candidats du Challenge 100 Jours ;
- aux formateurs qui accompagnent des debutants ;
- aux professionnels qui commencent a produire avec l'IA ;
- a toute personne qui veut utiliser l'IA sans perdre son jugement.

## Pre-requis

Avant de commencer, le lecteur doit :

- avoir un objectif de production simple ;
- savoir utiliser un prompt de base ;
- disposer d'un dossier pour classer ses documents ;
- accepter de relire et de corriger toute proposition IA.

## Comprendre le principe central

Une IA peut proposer un texte, une structure, une liste d'idees ou un exemple. Elle peut accelerer la production, mais elle ne connait pas toujours le contexte reel, le public exact, les contraintes du projet ou les consequences d'une erreur.

```text
L'IA propose.
L'humain decide.
L'atelier organise.
Le livrable prouve.
```

Copier une reponse sans la comprendre ne constitue pas une production professionnelle. Le document devient professionnel lorsque l'humain le cadre, le relit, le corrige, le classe et peut expliquer ses choix.

### Exemple concret

Un candidat demande a l'IA de rediger une fiche pedagogique. La reponse semble claire, mais elle contient un niveau trop avance et un exemple non verifie. Le candidat doit adapter le vocabulaire, remplacer l'exemple et verifier que la fiche correspond au livrable demande avant de la partager.

## Etape 1 - Piloter la demande

Piloter signifie definir le travail avant de demander a l'IA de produire.

### Actions

1. Nommer le livrable attendu.
2. Identifier le public vise.
3. Expliquer l'objectif concret.
4. Indiquer les contraintes de longueur, de ton et de format.
5. Preciser ce que l'IA ne doit pas inventer.

### Exemple de consigne

```text
Produis une fiche d'une page pour des debutants.
Utilise des phrases courtes.
N'invente aucun chiffre.
Signale les informations a verifier.
Retourne le resultat en Markdown.
```

### Resultat a verifier

La demande permet-elle de comprendre quoi produire, pour qui et selon quelles limites ?

## Etape 2 - Controler le contenu

Controler signifie comparer la proposition IA au besoin reel.

### Actions

1. Lire la reponse du debut a la fin.
2. Verifier les faits, chiffres, noms et dates importants.
3. Comparer le resultat au prompt et au plan valide.
4. Reperer les passages vagues, contradictoires ou trop affirmatifs.
5. Marquer `A VERIFIER` lorsqu'une information reste incertaine.

### Questions utiles

- Le document repond-il a l'objectif ?
- Le public peut-il comprendre le vocabulaire ?
- Les informations essentielles sont-elles exactes ?
- Le texte contient-il une promesse excessive ?
- Des informations absentes ont-elles ete inventees ?

### Resultat a verifier

Chaque information importante est comprise et controlee avant utilisation.

## Etape 3 - Corriger et adapter

Corriger ne consiste pas seulement a enlever les fautes. Il faut rendre le document juste, clair et utile pour son public.

### Actions

1. Supprimer les repetitions.
2. Raccourcir les phrases longues.
3. Remplacer les mots trop techniques.
4. Reorganiser les etapes si l'ordre n'est pas logique.
5. Ajouter uniquement les exemples que l'humain peut assumer.
6. Conserver une distinction claire entre brouillon IA et document V1.

### Resultat a verifier

Le candidat peut expliquer au moins trois corrections qu'il a effectuees lui-meme.

## Etape 4 - Valider la version utile

Valider signifie decider que le document est assez solide pour l'usage prevu. Cette decision appartient a l'humain habilite.

### Actions

1. Appliquer la checklist du livrable.
2. Faire relire le document si l'enjeu le justifie.
3. Verifier le nom, le statut et l'emplacement du fichier.
4. Noter les limites ou les points restant a confirmer.
5. Demander la validation du pilote lorsqu'elle est requise.

### Attention

Une V1 relue n'est pas automatiquement un document `VALIDE`. Dans le cadre LN-IA, seul le pilote humain peut confirmer ce statut.

## Etape 5 - Assumer et prouver le livrable

Assumer signifie pouvoir presenter le document, expliquer sa construction et reconnaitre ses limites.

### Actions

1. Enregistrer le fichier sous un nom clair.
2. Le classer dans le dossier approprie.
3. Conserver la trace du prompt utile.
4. Ajouter une preuve au portfolio.
5. Indiquer ce que l'IA a propose et ce que l'humain a corrige.

## Erreurs a eviter

| Erreur | Correction humaine attendue |
|---|---|
| Copier la reponse sans la lire | Relire chaque partie et expliquer le contenu |
| Utiliser un prompt trop vague | Preciser objectif, public, format et contraintes |
| Accepter une donnee inventee | Verifier la source ou supprimer l'information |
| Confondre V1 et version finale | Afficher le statut et demander la validation requise |
| Produire un document trop long | Garder uniquement ce qui aide le lecteur a agir |
| Exposer des donnees personnelles | Anonymiser et utiliser des exemples fictifs |
| Laisser l'IA decider | Conserver chaque decision importante sous controle humain |

## Checklist finale

- [ ] J'ai defini le livrable et son public.
- [ ] Mon prompt contient des contraintes claires.
- [ ] J'ai lu toute la proposition IA.
- [ ] J'ai verifie les informations importantes.
- [ ] J'ai supprime les elements inventes ou inutiles.
- [ ] J'ai adapte le vocabulaire au public.
- [ ] J'ai effectue une correction humaine visible.
- [ ] Le statut du document est correct.
- [ ] Le fichier est classe dans le bon dossier.
- [ ] La preuve portfolio est preparee.
- [ ] Aucune donnee sensible n'est exposee.
- [ ] La validation finale reste humaine.

## Mini-methode LN-IA en une minute

```text
1. Je cadre ce que je veux produire.
2. Je donne une consigne claire a l'IA.
3. Je lis et je controle la proposition.
4. Je corrige selon mon contexte reel.
5. Je classe le livrable et j'ajoute la preuve.
```
